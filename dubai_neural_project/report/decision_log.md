# Обоснование решений

## Исследовательский вопрос

Сравниваем точность и устойчивость моделей на предоставленном учебном наборе. Такой вопрос допускает высокий исходный R² и не требует искусственно ухудшать цифры. Шум — контролируемое воздействие с заранее заданными уровнями, а не средство получить «правдоподобную» метрику.

## Изменения по отношению к исходной версии

| Решение | Почему оно нужно | Ограничение или цена решения |
|---|---|---|
| Продолжить off_plan.csv | Сохраняет предмет уже начатой работы и сопоставимый источник | Выводы относятся к строящимся объектам, не ко всему рынку |
| Добавить TabResNet к MLP | Проверяет остаточную архитектуру вместо простого увеличения числа нейронов | Больше параметров; усложнение не гарантирует лучшей точности |
| Сохранить LightGBM и Random Forest | Даёт сильные нелинейные контрольные модели | Работа остаётся сравнением методов, а не демонстрацией гарантированного превосходства сети |
| Использовать Ridge вместо нерегуляризованной OLS в основном сравнении | Снижает нестабильность при коррелированных признаках | Линейная форма всё ещё плохо экстраполирует поздний период |
| Сравнить P и P/A на тех же строках | Прямо проверяет обсуждённую командой идею удельной цены | Это две постановки цели, не независимые датасеты |
| Для всех считать денежные метрики полной цены | Сравнение имеет единый смысл и единицы | Удельная модель должна дополнительно умножать на наблюдаемую площадь |
| Оставить одну площадь и логарифмировать её | Устраняет дублирование физической величины и стабилизирует масштаб | При ошибке площади теряется важная информация |
| Исключить ценовые производные и ID | Предотвращает восстановление ответа из самой цены и запоминание ID | Сами строительные характеристики проектов могут быть общими между временными частями |
| Кодировать категории одинаково one-hot для всех моделей | Нет искусственного порядка категорий; сравнение входов прозрачно | Нативные категории LightGBM могут быть эффективнее, но здесь не проверялись |
| Не удалять ценовые хвосты по квантилям всего набора | Полный test остаётся нетронутым, дорогие ошибки видимы | MAE и особенно RMSE чувствительны к редким дорогим объектам |
| Подбирать на 2024 и тестировать на 2025–2026 | Проверяется перенос вперёд по времени | Одна validation используется и для остановки, и для выбора кандидатов |
| Три кандидата на каждую обучаемую модель и цель | Ограниченный и обозримый поиск; 32 сочетания вместе с медианами | Это не доказательство глобального оптимума гиперпараметров |
| Сохранять manifest выбора до нового тестового расчёта | Можно проследить происхождение выбранных параметров | Сам тестовый период уже был известен из прежнего проекта |
| Три seed для каждой нейросетевой постановки | Не выдаёт удачную инициализацию за универсальный результат | Трёх повторов мало для точной оценки распределения |
| Разделить площадь, view, пропуски и метки | Можно объяснить, какое воздействие ухудшает модель | Не покрываются все возможные ошибки, например неверный район |
| Сохранить согласованность единиц площади | В исходнике футы и метры искажались независимо | В модели используется только площадь м² |
| Общие маски и парные сравнения | Различия моделей не смешиваются с разными повреждениями | Входные повторы проверяют маски, а не переобучение модели |
| При P/A использовать повреждённую площадь и в восстановлении P | Не даёт модели скрытую правильную площадь | Пропуски площади особенно болезненны, что и проявилось |
| Сохранять чистую validation и раннюю остановку при шуме цен | Эффект ошибок меток не смешивается с иной процедурой обучения | Выбранная эпоха/итерация всё равно может измениться |
| Проверить одну заранее заданную аугментацию | Даёт конкретный способ улучшения устойчивости | В этом опыте ошибка на чистом test выросла примерно на 8,6%, при 20% пропусков снизилась на 9,0% |
| Переставлять связанные признаки группами на validation | Снижает часть противоречий от независимой перестановки коррелированных полей | Межгрупповые связи могут нарушаться; это не причинная значимость |
| Bootstrap выбирать целые проекты | Учитывает общность объектов внутри project_id | Интервалы условны на обученных моделях и данном наборе |
| Добавить group holdout | Разделяет перенос на позднюю дату и перенос на новый проект | В групповом опыте даты смешаны; он не является прогнозом будущего |
| Добавить строгую проверку дат | Вскрывает существенный дефект набора и его последствия | После очистки уменьшается train и появляется 57 неизвестных проектов; сравнение не изолирует один фактор |
| Выполнить абляцию контекста | Идея Ясницкого об экономической среде проверяется, а не декларируется | Полученный эффект зависит от архитектуры и способа экстраполяции |
| Ограничить сценарии статусом диагностики | Метод «замораживания» показывает функцию модели | Связь ставки и даты не позволяет причинно интерпретировать изменение ставки |

## Что говорит результат

Выбранная по validation LightGBM на удельной цене лучше проверенных сетей на временном тесте. TabResNet при основном seed 42 лучше выбранной MLP, но её ошибка растёт при удалении от обучающего периода. Средние по трём seed подтверждают необходимость показывать разброс, а не только удачный запуск.

Групповой holdout даёт преимущество TabResNet, поскольку проверяет другую задачу. Именно поэтому нельзя сказать «эта модель лучше вообще». Основной вывод сформулирован по заранее выбранному временному протоколу; дополнительные проверки объясняют пределы вывода.

## Как использована литература Ясницкого

1. **Статья о недвижимости 2017 года, с. 72–74:** совместное использование характеристик объекта и контекста; самостоятельная проверка прогностических свойств. В проекте это временные части и абляция контекста. Описанная в статье нормированная на диапазон RMSE не отождествляется с MAPE нашего отчёта.
2. **Та же статья, с. 75:** исследование значимости по изменению ошибки. В проекте использована групповая перестановка без переобучения; это родственна по цели, но не идентична исходной процедуре исключения входа.
3. **Та же статья, с. 77–79:** изменение одного входа при фиксации остальных. В проекте это локальные сценарии площади и диагностический сценарий ставки с явным ограничением причинной интерпретации.
4. **Монография 2019 года, доступное введение, с. 6–7:** проблема изменения внешней среды. Содержимое недоступных глав не приписывается источнику.
5. **Статья о фигурном катании 2014 года, с. 2–5:** раздельные обучение и тестирование, затем вычислительные эксперименты. Предметные закономерности спорта не переносятся на недвижимость.

Не добавлялись ссылки на нерелевантные функции потерь, компьютерное зрение или статьи, которые не используются для аргументации проекта.
